# 3D Presentation Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the true-3D presentation feel finished: jersey numbers over players, actor shadows at high quality, a puck trail, a follow-the-puck camera mode with quick presets, and a fade-in entry.

**Architecture:** All work stays inside `src/render3d/` plus a 3D-only section of `ViewControls`. Every visual element remains a pure function of the current `PlaybackFrame` (or, for trails, of the same accumulation source the 2D board already uses), preserving scrub determinism. Camera modes extend `orbitFromCamera`'s inputs without touching the 2D camera store's semantics — follow mode only moves the TARGET, never writes tilt.

**Tech Stack:** three ^0.182 (already present), Pixi/Canvas 2D untouched.

## Global Constraints

- Rendering stays synchronous inside the playback frame listener; the only permitted self-scheduled rAF remains the existing idle-orbit/entry animations, which must stop themselves. dt for any animation derives from progress deltas or a bounded entry-transition clock — never an unbounded wall-clock loop.
- Follow mode and presets NEVER write `camera.tilt` (the 2D/3D mount switch depends on it) and never fight the user: any drag/wheel/pinch input immediately drops back to free mode.
- Ghost/puck trails reuse `PlaybackStore`'s accumulation pattern (`trails` / `GhostTrailBuffer`, cleared the same places) — no new wall-clock state; 3D reads the same source the 2D `drawGhostTrails` reads, or a parallel buffer maintained in the SAME `seek` path.
- Quality tiers: number sprites render at texture resolution 128px ('low') / 256px (otherwise); actor shadows only at `'high'` (the DirectionalLight shadow map already exists at 'high' — actors opt in with `castShadow`; verify frame cost on the perf project's playback numbers, report before/after).
- `npm run lint` zero warnings; typecheck clean; full unit suite green; `board3d` + `flows` e2e green; `tabletop rink` visual baseline: Tasks 1–3 WILL change it (numbers/shadows/trail visible) — regenerate ONCE at Task 3 (not per-task), two stable runs; budgets unchanged (no new deps).
- Out of scope: 2D board changes, new dependencies, editing in 3D, Present-mode tools (separate phase), gesture sensitivity retune (hardening phase).

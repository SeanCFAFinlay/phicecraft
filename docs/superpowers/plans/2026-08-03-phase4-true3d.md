# Phase 4 — True-3D Presentation + First-Party Asset Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the tabletop pseudo-3D view with a true-3D three.js presentation driven by the user's own rigged GLB models, and replace every unknown-provenance shipping image (sprite atlas, arena overhead) with first-party art baked from those models — clearing all remaining ASSET_REGISTER release blockers.

**Architecture:** The 3D view is a lazy React component (`Board3D`) that mounts in place of `CanvasSurface` whenever the camera enters tabletop range (`tilt > TABLETOP_MIN_TILT`); it consumes the SAME `PlaybackFrame` stream via `playback.subscribeToFrames` and reuses the existing camera store (tilt→polar, rotation→azimuth, zoom→distance). The ice surface is textured by rendering the existing `drawStaticLayer` to an offscreen canvas, guaranteeing marking parity with the 2D board for free. Player/goalie actors are `SkeletonUtils`-cloned GLB instances with material tinting (`jersey`/`accent` materials) and `AnimationMixer` clips (`skate` speed-scaled by `frame.speed`; `goalie_idle` for role `'G'`). The 2D sprite atlas is regenerated from the same GLBs by a repeatable bake script (Playwright + three.js + sharp). Once Board3D lands, the entire Canvas pseudo-3D pass (drawArenaBase/Walls/Players/Coaches, the WebGL buffer-blit fallback, arena-overhead.webp) is deleted.

**Tech Stack:** three ^0.182 (lazy chunk, GLTFLoader + SkeletonUtils + AnimationMixer from three/addons), Playwright + sharp for the bake script, existing PixiJS/Canvas2D 2D pipelines untouched except for atlas art and pseudo-3D deletion.

- Gates at every task: `npm run typecheck` clean; `npm run lint` zero warnings; full unit suite green; `npm run build && npm run check:budgets` green; visual baselines stable across two consecutive runs whenever they regenerate. jsdom cannot run three's WebGLRenderer — unit tests cover pure modules (node env) and DOM-free scene assembly; rendering itself is e2e/visual-verified.
